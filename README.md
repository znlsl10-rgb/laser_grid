## 파이프라인

```
입력 = 레이저 이미지(필수) + camera_params.json·cast_pixels.json·IMU(선택)
 │
 ├─[신호]  laser_signal.py   채널(R/G/B)을 이미지에서 재서 고른다
 ├─[A]     A_선검출.py        {lid: [(u,v)…]}        능선 추적
 ├─[eq7]   eq7_laser_plane   선별 평면 법선 n → 이득 g → (X,Y,Z)
 │           g = √(n_x²+n_y²)/|n_x| 가 '깊이를 줄 수 있는 선' 을 가른다
 │           (eq1 은 이 식의 특수해 — roll=0·tilt=0·V선. 규격 원식·회귀 기준)
 ├─[C]     C_영역분할.py       3D 점군 → 면/선형 분리 (다중평면 RANSAC)
 ├─[eq5]   eq5_region_assign  점→영역 할당, 경계 정제, 의미×기하 융합
 │
 ├─ 면 부재 (벽·바닥·거푸집·슬래브)
 │     eq2 평면(TLS) → eq3 수직도/수평도(중력) → eq4·eq6 평활도
 ├─ 선형 부재 (동바리·기둥·철근)
 │     eq2 축(RANSAC) → eq3 축 수직도(중력)   [평활도 정의 없음]
 │     격자선 1줄만 걸리면 → eq8 로 옆 성분 복원, 안 되면 판정보류
 │
 └─ eq5 불확실도 → 합격 / 기준초과 / 측정불가 / 판정보류
      ↓
    엑셀 조서 11시트 + 세그멘테이션 이미지 + 3D 점군(부재별 색) + 좌표 CSV
```

**면이냐 선형이냐** 는 점군 모양만으로 갈린다 — 설정값이 아니다. 갈리지
않는 것은 **어느 검사를 걸 것인가**(수직도냐 수평도냐)로, 그건 장비 자세를
알아야 정해진다. 그래서 `camera_params.json` 도 IMU 도 없이 돌리면 값은
그대로 내되 판정은 **참고값(판정보류)** 으로 낮춘다. 실측에서 바닥 캡처를
이미지만으로 돌렸을 때 `4.4594° 기준초과` 가 나왔는데, 같은 캡처에 사양
파일을 함께 넣으면 `0.0390° 합격` 이다 — 부재가 기운 게 아니라 장비가
숙여 있었을 뿐이다.

**세로선(V)과 가로선(H)은 같은 식으로 푼다.** eq7 이 선을 발사각이 아니라
레이저 평면 법선 n 으로 다루므로, 깊이가 풀리는지는 "V선인가 H선인가" 가
아니라 이득 `g = √(n_x²+n_y²)/|n_x|` 하나로 정해진다. 자세한 것은 아래
**가로선(H선)은 언제 쓸 수 있는가** 절.

**세그멘테이션은 레이저 OFF 프레임을 쓴다.** ON 프레임은 초록 격자선이 화면을
덮어 모델이 선을 물체 경계로 오인한다. 하드웨어는 차영상 모드를 위해 이미
ON/OFF 두 프레임을 수십 µs 간격으로 찍으므로, 마스크가 픽셀 단위로 그대로
정합된다. 추가 비용 없이 문제가 사라진다.

```bash
    --truth cast_pixels.json \                       # 선택 — 정확도·깊이 오차표
    --scene CAM.png                                  # 선택 — 결과 그림 배경
```

코랩은 `colab.ipynb` 를 열면 된다 ([Colab에서 열기](https://colab.research.google.com/github/znlsl10-rgb/laser_grid/blob/main/colab.ipynb)).

가진 정보에 따라 두 갈래로 갈린다.

| 경로 | 조건 | 하는 일 |
|---|---|---|
| **정밀** | 사양 + 정답 3D + 장비 자세가 모두 있을 때 | 발사각·기선 부호·카메라 자세를 데이터에서 복원한다. 가정이 거의 없다 |
| **기본** | 이미지만, 또는 사양까지만 | 격자를 이미지에서 직접 읽어 **측정거리와 화소 규약을 복원**하고, 중력은 IMU 가 없으면 똑바로 섰다고 가정한다 |

기본 경로도 거리·규약을 스스로 찾으므로 정밀 경로와 같은 각도를 낸다
(실측: 벽 수직도 0.0074° 로 양쪽 동일, 복원 거리 1.548m vs 참값 1.548m).
무엇을 가정했는지는 조서 1번·11번 시트에 그대로 적힌다.

**IMU 형식** — 셋 중 아무거나.

```json
{"pitch_deg": 34.0, "roll_deg": 0.0}
{"gravity": [0, 0.83, 0.56]}
{"accel":   [0, -0.83, -0.56]}
```

IMU 를 안 주면 똑바로 서 있다고 봅니다. 수직도는 면 법선과 중력의
사잇각이라 **장비가 1° 기울어 있었으면 판정도 1° 틀립니다** — 허용치가
±0.5° 인 것을 생각하면 작지 않습니다.

### 검측 흐름 — 실장비가 하는 일과 같은 순서

```
[1] 선검출     CAST.png(레이캐스트 렌더) → A_선검출 → 화소 (u,v)
                └ raycast 정답 화소와 대조해 검출 정확도를 잰다
[2] 3D 복원    화소 → eq7 삼각측량 → (X,Y,Z) 조사기 좌표
                └ raycast 참값과 깊이를 직접 맞대 mm 로 확인한다
[3] 검측       영역분할 → 부재별 수직도·수평도·평활도
[4] 산출       3D 점군 그림 · 세그멘테이션 · 엑셀 조서
```

**검측에 들어가는 화소는 기본이 "검출 화소"다.** 실장비에는 정답 화소가
없으므로 그래야 현장에서 나올 값이 조서에 실린다. `--source gt` 는
"카메라가 완벽했다면" 의 상한을 볼 때만 쓴다.

| 시트 | 내용 |
|---|---|
| 1.요약 / 2.설계값 | 촬영 조건, 사양 출처 등급 |
| 3.선검출(1단계) | 계열별(V·H) 검출 성적, 오차 분해, **선검출 대조 그림** |
| 4.깊이검증(2단계) | 검출 화소로 푼 3D 를 raycast 참값과 맞댄 mm 오차 |
| 5.세그멘테이션(3단계) | 색↔부재 대응표 + **세그멘테이션 그림** |
| 6.검측결과 | 부재별 수직도·수평도·평활도 판정 (본문) |
| 7.평활도상세 / 8.요철위치 | 직선자 처짐 근거, 요철 좌표 + **그림** |
| 9.3D좌표(부재별) | 점수·중심·외접상자·선구성 + **3D 점군 그림** |
| 10.3D좌표(점목록) | 부재 구분이 붙은 좌표 목록 |
| 11.유의사항 | 이 조서를 읽을 때 반드시 아는 것 |

3D 좌표의 중력 정렬 좌표(가로·깊이·높이)는 **장비 광학중심이 원점**이다.
절대 표고가 아니므로 표고로 바꾸려면 장비 설치 높이를 더해야 한다 — 그
값은 이 장비가 알 수 없다.

| `eq8_silhouette.py` | **옆(레이저 평면 수직) 기울기 복원**. 세로선 한 줄이 원리적으로 못 보는 성분을 부재 그림자에서 되찾는다 — ① 가로선 화소의 끊김 ② 원신호 그림자 스캔 |

## 설계상 중요한 결정

### 1. 중력 기준으로 통합했다
기존 식은 벽에 `arcsin(|n_y|)`, 바닥에 `arccos(|n_z|)` 로 **서로 다른 축**을
읽었다. 이는 "장비를 각 면에 정면으로 겨눈다"는 전제에서만 성립하는데, 한 장에
벽(정면)과 바닥(경사)이 함께 들어오면 두 면에 동시에 정면일 수 없다.

```
벽(면)      θ = arcsin(|n̂ · ĝ|)      완전수직 → 0°
바닥(면)    θ = arccos(|n̂ · ĝ|)      완전수평 → 0°
동바리(축)  θ = arccos(|d̂ · ĝ|)      완전수직 → 0°
```

기존 식은 `ĝ=(0,1,0)` / `(0,0,1)` 인 특수해이므로 검증값이 그대로 재현된다.
부수적으로 v1 자체검증이 수평도에서 88°(참값 2°)로 실패하던 문제가 사라졌다.

### 2. 평면적합을 방향 무관으로 바꿨다
`Z = aX + bY + c` 회귀는 광축과 나란한 면(비스듬히 들어온 바닥)을 표현할 수
없다. 경사 바닥 실측 법선오차 **8.45° → 0.0013°**, 정면 벽은 양쪽 동일.

### 3. 동바리·철근은 평면이 아니다
1D 선형 부재이므로 축을 적합한다. 얇은 부재는 마스크 실루엣에서 반드시
오염되므로 **RANSAC 축 적합**을 쓴다 (오염 16%에서도 정답 복구).

### 4. 평활도는 KCS 직선자로 판정한다
전역 평면 잔차와 자 처짐량은 다른 값이다.

| | eq4 전역잔차 | 3m 자 처짐 |
|---|---|---|
| 전역 휨 12mm | 7.90mm | 0.54mm |
| 국소 융기 6mm | 0.72mm | 4.67mm |

eq4 는 요철의 **위치**를 찾고, eq6 이 **판정**한다.

### 5. 판정하지 않는 상태를 따로 둔다
- **측정불가**: σ_n = σ_Z/cos(입사각) 이 목표(±2mm)를 넘어 값 자체를 못 믿음
- **판정보류(분해능)**: 값은 허용 이내이나 요철 폭이 분해능보다 좁아 하한값임
- **판정보류(노출길이)**: 부재가 짧게만 보여 각도 불확실도가 허용치를 넘음
- **판정보류(단면 미분해)**: 격자선이 **한 줄만** 걸려 각도의 한 성분만 보임

마지막 것이 특히 위험하다. 한 줄에서 나온 3D 점은 삼각측량의 정의상
**그 레이저 평면 안**에 놓인다. 그러면 축 적합이 찾는 것은 부재의 축이
아니라 부재 표면과 그 평면의 교선이고, 교선은 평면 안에서만 기울 수 있다.

```
평면 안 기울기        → 보인다
평면에 수직인 기울기   → 전혀 안 보인다   →  잰 값은 참값의 하한
```

검증 실험: 실제로 **2.00° 기운** 부재를 한 줄로 보면 **0.0000°** 로 나온다.
그래서 합격 판정을 막는다. 실측에서도 동바리 세 본이 전부 "수직도 0.0000°
합격" 으로 나왔는데, 그 0 은 측정값이 아니라 기하의 결과였다.

### 5-2. 가로선이 그 부재를 21번 지난다 — 그림자로 되찾는다 (eq8)

세로선은 한 줄이지만 **가로선은 같은 부재를 21번 가로지른다**(21선 × 3본
= 63 교차). 가로선 자체는 깊이를 못 주지만, 부재가 뒤 배경에 드리우는
**가림 그림자**는 화면에서 또렷하다. 카메라가 조사기에서 기선 b 만큼
떨어져 있어, 레이저가 부재에 막혀 못 간 자리가 어둡게 남는다.

```
그림자 폭  w = f·b·(1/Z_부재 − 1/Z_배경)   [px]
예측 27px  ↔  실측 25~26px          ← 이 일치가 안전장치다
```

그림자가 시작하는 자리가 곧 **부재의 실루엣 가장자리**다. 부재의 깊이는
세로선에서 이미 알고 있으므로, 가장자리 화소를 그 깊이에 놓으면 3D 점이
되고, 높이마다 모아 직선을 맞추면 **평면에 수직인 성분까지** 나온다.
두 성분은 직교하므로 제곱합으로 합친다.

실측 — 세 본 모두 참값 0°(가장자리가 21행 내내 고정):

| | 평면 안 | 옆(그림자) | 합 | 잔차 | 판정 |
|---|---|---|---|---|---|
| 동바리 1 | 0.0000° | 0.0094° | 0.0094° | 0.35px | 합격 |
| 동바리 2 | 0.0000° | 0.0089° | 0.0089° | 0.35px | 합격 |
| 동바리 3 | 0.0000° | 0.0085° | 0.0085° | 0.34px | 합격 |

**되살아나지 않으면 판정보류를 그대로 둔다.** 조용히 합격으로 바꾸지
않는다. 가장자리가 직선이 아니면(잔차 > 2.5px) 그림자 아닌 끊김을 잡은
것이므로 버린다 — 실제로 이 게이트가 없을 때 한 본이 없는 기울기
0.36° 를 지어냈다(참값 0°). 뒤에 배경이 없으면 그림자 자체가 안 생겨
역시 판정보류로 남는다(바닥 장면의 동바리가 그랬다).

근본 해결은 여전히 격자를 조밀하게 하는 것이다 — 1.6m 에서 legacy 피치
94mm > 동바리 Ø48.6mm 라 세로선이 한 줄뿐이었다. `improved`(V40)면
1.2m 에서 피치 24mm 로 두 줄 이상 걸린다.

### 5-1. 크기는 "부재 길이" 가 아니다

선형 부재의 높이폭은 **격자가 닿은 구간**이지 부재 길이가 아니다. 실측에서
동바리 세 본이 1.99 / 1.93 / 1.87m 로 나와 길이가 다른 것처럼 보였지만,
거리 1.705 / 1.652 / 1.595m 에 정확히 비례한 값이었다 — 셋 다 같은 화소
구간을 서로 다른 거리에서 본 것이다. 조서 9번 시트의 「크기 해석」 열이
이 구분을 매 행에 적는다.

과소평가는 기준초과를 합격으로 내보내는 방향이라, 이 구분이 없으면 위험하다.
(실측: GT 8mm 융기 → 자 처짐 5.6mm → 허용 7mm 대비 거짓 "합격")

### 6. 가로선(H선)은 언제 쓸 수 있는가

`A_선검출` 은 예전부터 가로선을 추적하고 있었다(Step4). 실측 검출률은 21/21,
선 위 잡음 0.0001~0.003px 로 세로선보다 오히려 깨끗하다. 그런데도 검측에는
한 점도 못 들어갔다. 이유는 검출이 아니라 **기하** 다.

레이저 평면 `n·P = 0` 과 카메라 `C=(b,0,0)` 에서

```
Z = − n_x·b / (n_x·û + n_y·v̂ + n_z)          û=(u−c_x)/f, v̂=(v−c_y)/f
```

깊이가 풀리는지는 오직 `n_x ≠ 0` 에 달렸고, 감도는 하나의 무차원 수로 모인다.

```
g = √(n_x² + n_y²) / |n_x|          σ_Z = g · σ_perp · Z²/(f·b)
```

굴리지 않은 격자에서 H평면의 법선은 `(0, −cosβ, sinβ)` — `n_x = 0` 이라
`g = ∞` 다. 평면이 기선(X축)을 품어 시차가 선과 나란해지기 때문이다.
**가정이 아니라 측정으로 확인된다.** 내보내기의 raycast 점에 평면을 직접
맞추면(잔차 0.0006~0.33mm) 세 장면 모두 `|n_x| = 0.000000` 이 나오고, 정답
가로선의 v 는 1500점에 걸쳐 **0.0004px** 밖에 안 움직인다 — 검출 잡음
0.26px 의 1/650 이다. 읽어낼 신호 자체가 없다.

살리는 방법은 DOE 를 **광축 둘레로 γ 만큼 굴리는 것** 하나다.

| 굴림 γ | V선 g | H선 g | 깊이 주는 선 (30+30 기준) |
|---|---|---|---|
| 0° | 1.00 | ∞ | 30 |
| 15° | 1.03 | 3.86 | 30 (H 는 문턱 g≤3 초과) |
| 30° | 1.16 | 2.00 | 60 |
| 45° | 1.41 | 1.41 | 60 |

γ=45° 는 두 계열의 이득이 같아지는 유일한 각이다. 수렴각(tilt, Y축 둘레)으로는
안 된다 — 중앙 H선(β=0)에서 발산하고 가장자리에서도 g가 16을 넘는다.

**굴림은 공짜가 아니다.** 합성 씬 실측(4회 평균, 격자 30×30):

| 구성 | 벽 수직도 | 바닥 수평도 | 동바리 수직도 | 평활도 오차 |
|---|---|---|---|---|
| improved (굴림 0°, V40) | 0.0131° | 0.0029° | 0.0270° | 0.098mm |
| 굴림 30° (V30+H30) | 0.0070° | 0.0032° | **0.0032°** | 0.357mm |
| 굴림 45° (V30+H30) | **0.0054°** | 0.0040° | 0.0223° | 0.237mm |

각도는 좋아지고 평활도는 나빠진다. 방향이 갈리는 이유는 통계량이 다르기
때문이다. 각도는 많은 점을 **평균** 하므로 표본이 늘면 이긴다. 평활도는
직선자 아래 **가장 큰 틈** 이라 극값 통계이고, 점당 잡음이 `1/cos γ` 배로
커지면 극값이 그대로 위로 밀린다.

즉 "가로축을 살리면 세 가지가 다 좋아진다" 는 아니다. **수직도·수평도는
확실히 좋아지고, 평활도는 내주는 거래다.** 어느 쪽을 살릴지는 현장 검측
항목이 정한다. `experiment_roll.py` 로 실제 사양·장면에서 다시 재면 된다.

#### 굴린 격자는 선검출기도 달라야 한다

굴리면 두 계열이 **모두 대각선** 이 된다. 행을 훑으며 u 를 찾는 기존
추적기는 한 행에서 V선과 H선을 함께 만나고, 교점 근처에서 둘이 몇 px 로
붙으면 옆 계열 능선을 물고 따라간다. 실측으로 45° 굴림에서 14선 중 3선만
제대로 잡혔고, 어긋난 선은 최대 662px 옮겨 앉았다. 두 가지를 넣어 고쳤다.

1. **능선 방향으로 계열 분리** (`_family_masks`) — 두 계열은 서로 직교하므로
   구조텐서로 능선 방향을 재어 각 화소를 가까운 쪽에 준다. 임계값 없는
   하드 분할이라 맞출 파라미터가 없다.
2. **선 방향 추적** (`_trace_line_oriented`) — 행이 아니라 **선 자신의 방향**
   으로 걸으며 법선 방향으로만 훑는다. 이미지를 돌리지 않는다 — 45° 회전
   리샘플링은 화소 격자에 안 떨어져 서브픽셀에 계통 오차를 남긴다(이
   저장소는 180° 뒤집기에서 같은 이유로 0.96px 오차를 겪었다). 원본 화소를
   겹선형으로 읽을 뿐이다. 밴드 폭은 **수직 방향 실제 선 간격**(`_perp_spacings`)
   에서 뽑는다. u 축 간격을 쓰면 45° 에서 1.41배 넓게 잡혀 옆 선을 문다.

렌더 → 검출 → 정답 대조 실측 (단일 평면, 14+14 격자):

| 굴림 | V선 | 편차 | 산포 | H선 | 편차 | 산포 |
|---|---|---|---|---|---|---|
| 0° | 14/14 | −0.146px | 0.007px | 14/14 | +0.172px | 0.099px |
| 45° | 14/14 | −0.099px | 0.058px | 14/14 | +0.000px | 0.035px |

굴린 격자가 굴리지 않은 것만큼 잘 잡힌다. 굴림 0° 경로는 손대지 않았고
(`normal` 이 있고 V선이 세로에서 10° 이상 벗어날 때만 새 경로를 탄다),
실제 캡처 결과는 변경 전후가 같다(σ_u 0.263px, 계통 −0.041px).

## 선검출 정확도의 한계는 이미지가 정한다

알고리즘을 아무리 다듬어도 못 넘는 바닥이 있다. 선이 안티에일리어싱
없이 **이진(0/255)** 으로 그려져 있으면 켜진 화소가 전부 같은 값이라,
중심을 어떻게 구하든 결과가 0.5px 격자 위에만 떨어진다. 그 격자에
균등분포한 오차의 표준편차가

```
σ_floor = 1/√12 = 0.289 px
```

제공된 표본이 정확히 이 경우다 — 켜진 화소의 100% 가 255, 선폭 2px.
그리고 실측 검출 σ 는 **0.263px** 로 이미 이 바닥에 닿아 있다. 즉
서브픽셀 추정기는 더 짜낼 것이 없고, 남은 오차는 입력의 성질이다.

`run_pipeline.py` 는 이 하한을 이미지에서 자동으로 재어 조서에 적고,
정답이 없을 때는 σ_u 를 이 값으로 잡는다(가정값 0.2px 를 쓰면 실제보다
좋게 나와 평활도를 잘못 합격시킨다).

### 그럼 어떻게 줄이나 — 통제 실험으로 잰 값

같은 장면·같은 추정기로 해상도와 렌더 방식만 바꿔 측정했다.

| 저장 해상도 | 렌더 | σ_u (센서px) | 깊이 σ @1.55m |
|---|---|---|---|
| 1269×1063 | 이진 | 0.577 | **5.80 mm** ← 지금 입력 |
| 1269×1063 | AA | 0.398 | 4.00 mm |
| 2448×2048 | 이진 | 0.295 | **2.97 mm** |
| 2448×2048 | AA | 0.204 | **2.05 mm** |

1. **원해상도로 저장한다 (약 2배).** 화면 캡처를 1269px 로 줄여 저장하면
   센서 2448px 의 서브픽셀 정밀도를 그 배율만큼 버린다. 촬영 설정만
   바꾸면 되는, 가장 싸고 큰 지렛대다.
2. **안티에일리어싱을 켠다 (추가 1.4배).** 선 가장자리에 밝기 기울기가
   생겨 중심을 화소 사이에서 읽을 수 있다.
3. **`--smooth N` — 선을 따라 평활 (비스듬한 면에서 1.5배).**
   보정량을 양자화 반폭으로 묶으므로 "측정이 애초에 구분 못 한 구간
   안에서만" 점을 움직인다. 실측 바닥 4.32 → 2.93mm. 다만 창 너비보다
   좁은 요철은 뭉개지므로 기본은 꺼 둔다.
   정면 벽에서는 효과가 없다 — 세로선이 모든 행에서 같은 격자 위상에
   놓여 반올림 오차가 선 전체에 같은 값으로 실리기 때문이다(5.08→4.99mm).
4. **하드웨어.** σ_Z = σ_u·Z²/(f·b) 이므로 기선 b·초점거리 f 를 늘리거나
   측정거리 Z 를 줄인다. Z 는 제곱으로 들어가 가장 세다 — 2.7m 에서
   1.5m 로 다가서면 오차가 1/3 이 된다.

조서 4번 시트가 이 표를 **이 입력의 실제 숫자로** 계산해 싣는다.

### 해 보고 버린 것

**선별 상수 편차 제거** — 정면 벽의 오차는 선마다 다른 상수다(선간편차
0.256px vs 선내 0.024px). 면을 맞춰 그 편차를 빼면 될 것 같지만, 실제로
해 보니 깊이 오차가 **5.08 → 10.01mm 로 두 배 나빠졌다**. 선별 잔차에는
양자화뿐 아니라 **진짜 면 모양(요철)** 이 섞여 있어, 빼면 실재하는 기하를
지운다. 3차 추세만 남기고 고주파만 빼도 마찬가지였다. 양자화와 표면
형상은 이 데이터만으로 분리되지 않는다.
